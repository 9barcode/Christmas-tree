# BM v3 구현 및 서버 적용 안내

## 구현 범위
- 최초 진입은 기존 트리 꾸미기. 초록 트리 1개, 추가 슬롯 UI와 슬롯 해제 버튼 제거.
- 하단 메뉴: 트리 꾸미기 / 장식 공장 / 보관함 / 도감. 페이지 이동 시 배치 유지.
- 기존 장식 30종 재사용. 시안 원본 3장 `docs/images/ornament-*-concept.png` 포함.
- 공장은 승인된 시안 원본 `assets/factory/concept-original.png`를 그대로 사용한다. 산타·화로·벨트·선물의 구도와 화풍을 재생성하지 않는다. 원본 위에 실제 생산량·버튼을 좌표로 연결하고, 원본 픽셀 영역을 Canvas에서 미세 이동해 산타 호흡·벨트 진동·생산 조명만 추가한다. 신규 생성 배경/산타는 공장 화면에서 사용하지 않는다.
- 벨트 저속 루프, 산타 idle/생산 흔들림, 원본 상자의 빛과 장식 공개(2.2초), 건너뛰기. 소진 시 벨트 정지·조명 어둡게, 야근 성공 시 다시 가동. 모션 감소 설정/화면 비표시에서는 반복 정지. **하품/손동작 별도 프레임 애니메이션은 포함하지 않음.**
- 보관함 가치 필터, 수량, 배치·회수, 판매 확인, 잔액·교환 내역. 별/전구줄은 각 한 개, 트리 배치는 최대 30개.
- 도감 30종, 미획득 실루엣, 획득 후 판매해도 영구 보존, 최초 한 번 30원 보상.
- 서버에서 추첨·개별 아이템 소유권·판매 금액·원장·도감·KST 생산량·야근·배치 revision 관리. 실제 지급은 기존 지급 상태 머신을 v3 원장에 맞게 분리.

## 서버 담당 적용 순서
1. 기존 DB 백업 후 `npm run db:migrate:remote`로 `0006_factory.sql`, `0007_ad_gates.sql` 순서로 적용. 기존 테이블 삭제/초기화 없음.
2. 확정 카탈로그는 `wrangler.jsonc`의 `TREE_FACTORY_CATALOG`에 포함되어 Worker 배포 시 적용된다. 전체 30종의 판매 가치와 가중치는 [핵심 기획](bm-v3-factory-collection.md)의 표와 일치한다. 변수가 아예 없으면 `src/factory-model.js`의 동일한 기본 카탈로그를 사용한다. 명시적으로 등록한 변수가 잘못된 JSON·중복·누락·잘못된 값이면 기존과 같이 생산을 차단한다. 별도 운영 변수로 덮어쓸 경우 확정 구성을 유지해야 하며, 저장소 설정을 통한 다음 배포 시 저장소 값이 적용된다.
3. 기존 `REWARDED_AD_GROUP_ID` 한 개를 생산·야근에 공용 사용. 기존 문구형/이미지형 로딩 배너 유지. 트리 화면 배너는 중단.
4. 기존 `TOSS_MTLS`, `TOSS_PROMOTION_MODE`, `TOSS_PROMOTION_CODE_EXCHANGE`로 지급 연결. 미설정이면 교환 비활성화. 테스트 모드 완료는 실지급 없이 예약 잔액 복원.
5. Worker 배포 후 프런트 빌드/배포. 이 커밋 자체는 운영 DB 마이그레이션이나 배포를 수행하지 않는다.

## 데이터 보존
- 기존 1번 트리 장식과 화분/장식 좌표는 첫 진입 시 한 번 복사해서 표시한다. 기존 장식의 가치는 0(판매 불가)이고 신규 도감/완성 보상에 자동 합산하지 않는다. 기존 장식을 현금 가치로 임의 전환하거나 이미 받은 보상을 재지급하지 않기 위한 보수적 이관이다.
- 기존 2~5번 트리, 보상 원장, 미지급 v2 보상은 원본 테이블에 보존. v3 UI에서 추가 슬롯으로 노출하지 않는다. 이들 보상의 정산/이관 정책은 별도 확정 필요.
- 신규 데이터는 `tree_factory_*` 테이블에 분리. v2 지급 데이터에 접근하거나 금액을 합산하지 않는다.

## 실제 광고 검증의 경계
현재 플랫폼 연동은 기존과 동일하게 SDK `userEarnedReward` 결과를 로그인 세션과 서버 예약에 연결한다. 클라이언트의 완료 이벤트 보고 자체를 독립적인 광고 서버 증빙으로 간주할 수는 없다. 요청/아이템/판매/보상 중복 방지는 구현했지만, 조작된 클라이언트의 광고 완료 위조까지 방어한다고 주장하지 않는다. 현금성 보상으로 운영하기 전에 플랫폼에서 사용할 수 있는 독립 검증 수단을 확인·연결해야 한다.

## 미리보기와 확인
- `npm start` 후 `http://localhost:4173/?preview=1`에서 외부 광고·실지급 없이 UI를 확인한다. 미리보기는 확정된 기본 카탈로그의 판매 가치와 서버와 동일한 가중 추첨 함수를 사용하며 실제 잔액·광고·지급과 분리된다.
- 미리보기는 새로고침 시 초기화. 실제 앱은 인증된 서버 상태를 사용.
- `npm test`: 기존 테스트와 실제 SQLite로 생산 한도·중복 완료·보관/판매·도감·배치 충돌·구 데이터 보존 검증.
- `npm run build`: Toss용 웹 패키지 생성. 토스 단말 광고/실지급 QA는 별도 필요.

## 제작 프롬프트 요약
- 기본 내장 이미지 생성 도구 사용. 기존 공장 시안 참조, 따뜻한 우드·크림·초록·버건디의 둥근 붓터치 스타일.
- 배경: 창·리스·화로·전구·컨베이어, 인물/글자/UI 제외.
- 산타: 클립보드를 양손에 든 전신 산타, 투명 배경, 단일 캐릭터, 글자/UI 제외.

### 이전 BM v3 구현 당시 검증 결과
- `npm test`: 62개 통과 (신규 실제 SQLite 기반 통합 검증 5개 포함).
- `npm run build`: 통과.
- `wrangler deploy --dry-run`: Worker 번들 생성 통과, 운영 배포 없음.
- 헤드리스 Chromium: 390px 페이지 이동·생산·배치 확인. 320px에서 생산 10회→야근 해제→판매→영구 도감 유지→사진 준비 확인. 페이지 오류·가로 넘침 없음.
- 신규 장식 썸네일 30개 WebP로 최적화, 기존 원본 유지. 주아체 전체 한글 WOFF2를 추가해 신규 문구 누락 해결 (기존 `assets/fonts/OFL-Jua.txt` 라이선스 동일 적용).

## 공장 시안 일치 수정
- 원본 시안 전체 구도를 유지하며 실제 버튼과 생산량을 겹쳐 연결. 야근 버튼은 기본 10회 소진 전 비활성화.
- 별도 생성 캐릭터·기계·CSS 벨트 대신 원본 그림 자체에 국소 모션 적용. 정지/모션 감소 설정에서는 원본 정지 이미지.

## 트리 레이어·하단 버튼·생산 준비 상태 수정
- 화분 뒤 테두리는 트리 뒤 레이어에 고정하고 앞면만 바닥 깊이에 따라 정렬한다. 이전 기본 화분 좌표도 정규화한다. 사진 렌더링도 같은 레이어 순서를 사용한다.
- 이용안내·보상내역·사진 저장/공유는 하단 탭 바로 위에 고정. 공장·보관함·도감에서는 숨긴다. 사진 버튼에는 따뜻한 금색·초록 카메라 아이콘을 추가한다.
- 시안 그림의 오타는 실제 UI 텍스트 ‘오늘의 생산량’으로 대체한다.
- `productionReady=false`이면 광고처럼 보이는 비활성 버튼 대신 ‘생산 준비 상태 확인’으로 원인을 안내한다. 카탈로그가 잘못되었거나 광고 설정이 없으면 장식을 지급하지 않는다. 카탈로그 변수가 없는 경우에는 확정 기본값을 사용한다.
- 실제 생산은 이번에 확정한 30종 카탈로그와 기존 `REWARDED_AD_GROUP_ID`를 사용한다. Worker 배포 시 저장소의 카탈로그 변수를 적용하며 광고 그룹은 기존 값을 유지한다.
- 야근수당 버튼은 처리 중일 때만 비활성화한다. 기본 10회 미완료 시 현재/남은 횟수, 당일 사용 완료 시 하루 1회 및 한국시간 자정 초기화, 생산 설정 미완료 시 준비 사유를 팝업으로 안내한다. 조건 미충족 클릭은 광고나 횟수 지급을 실행하지 않는다.

## 2026-10-22 확정 판매 가치·뽑기 확률 적용
- 1원 18종: 그룹 확률 70%, 아이템당 가중치 245.
- 2원 7종: 초록 큰 선물, 전구줄, 과자집, 루돌프, 목마, 산타 모자, 눈사람. 그룹 확률 20%, 아이템당 가중치 180.
- 3원 5종: 아이보리 방울, 눈 덮인 집, 테디베어, 미니카, 황금 별. 그룹 확률 10%, 아이템당 가중치 126.
- 나머지 18종은 모두 1원. 전체 가중치 6,300을 사용하며 같은 가치 내에서는 동일 확률이다.
- 기존 서버 가중 추첨을 그대로 사용한다. 광고 완료 시 확정된 판매 가치를 신규 아이템에 저장하고, 판매 시 저장한 금액을 적립한다. 기존 발급 장식·판매 내역·잔액·도감·기존 가치 0 이관 장식은 재계산하지 않는다.
- 미리보기의 임시 1/2/3원 순환값과 순차 획득을 제거하고 동일한 확정 금액·가중 추첨을 사용한다.
- Worker 자동 배포 경로에 `src/factory-model.js`를 포함하여 모델 수정 시 서버 번들도 갱신한다.
- 적용: PR 병합 후 Worker 배포 성공을 확인하고 Release AIT를 다시 빌드하여 업로드한다. 이 변경 작업에서 직접 운영 배포하거나 DB 데이터를 변경하지 않는다.
- 이번 변경 검증: JavaScript 문법 검사, `git diff --check`, `npm run build`, `node scripts/build-web.mjs --release`, `wrangler deploy --dry-run` 통과. 테스트 코드는 작성·실행하지 않았다. 위의 테스트 통과 수치는 이전 구현 당시의 기록이다. 토스 AIT 업로드와 실제 광고·지급 확인은 배포 후 별도로 진행한다.
