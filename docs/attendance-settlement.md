# 연속 출석 마무리와 포인트 수령

2026-10-16 확정. 이전의 ‘결석 후 계속 꾸미기’ 설명보다 우선한다.

- 한국 날짜 기준 마지막 출석일의 다음 날까지 이어서 출석할 수 있다. 하루 전체를 쉬어 마지막 출석일과 오늘의 차이가 2일 이상이면 해당 트리의 꾸미기를 마무리한다.
- 출석을 시작하지 않은 0회 트리는 적용하지 않는다. 트리별로 독립 판정한다.
- 마무리한 트리는 장식 추가 및 위치 변경을 할 수 없다. 기존 트리와 장식은 그대로 전시한다.
- 출석 1~N일의 보상은 1+2+…+N = N(N+1)/2 P. 5일은 15P, 30일은 465P. 30회 완성에도 수령 흐름을 제공한다.
- 버튼: `광고 보고 트리의 선물 받기 · {금액}P` → `트리의 선물 확인하기`(지급 결과 확인 필요) → `트리의 선물을 받았어요`(서버 지급 완료).
- 안내: ‘하루 쉬어 가면 꾸미기를 마무리해요. 광고를 보고 출석한 날까지 모은 포인트를 받아요.’
- 버튼에 실패·종료·실격 등 부정적인 단어를 쓰지 않는다.
- 수령 뒤 초기화/새 트리 생성 규칙은 추가하지 않았다. 완성 전시와 기존 슬롯 해제 상태를 보존한다.

## 프론트엔드 연동 계약

현재 저장소에는 실제 지급 API/광고 SDK가 없으므로 **실제 포인트 지급은 아직 동작하지 않는다**. 미연결 상태에서는 모은 기록을 보관하고 안내만 표시한다. 로컬 완료 값을 근거로 지급을 승인해서는 안 된다.

호스트가 인증된 `window.treeRewards`를 제공한다.
- `prepare({treeId})`: 서버 시간·출석 원장으로 수령 가능 여부와 금액을 계산하고, 고유 `rewardRef`, 정수 `amount`, `status: ready | pending | paid`를 반환한다. 클라이언트 금액은 받지 않는다.
- `claim({treeId,rewardRef,adReceipt})`: 광고 완료 증빙과 예약을 서버에서 확인하고 동일 rewardRef는 중복 지급하지 않는다. 지급 결과의 rewardRef/amount/status를 반환한다.
- `getStatus({treeId,rewardRef})`: 확정/처리 중/재시도 가능 상태를 반환한다. 준비 중에는 광고를 다시 요구하지 않는다.
- `window.treeAds.showRewarded({purpose:'attendance-settlement',rewardRef})`: 완료 시 `{rewarded:true,adReceipt}` 반환. 단순 rewarded boolean을 서버 지급 증빙으로 믿으면 안 된다.

서버 지급 요청 직전 pending을 저장한다. 네트워크가 끊어져도 다음 요청은 상태 조회로 진행한다. 지급 확정 전에는 트리나 보상 기록을 지우지 않는다. 서버 미연동 단계의 날짜와 금액 표시는 기기 기준 프론트엔드 값이며 운영 출석/지급의 권위가 아니다.

검증: 동일일·다음날·하루 건너뜀·0회·30회, 지급 어댑터 미연결, 광고 미완료, 지급 대기 재조회, 지급 응답 유실 테스트.

홈 안내: ‘차곡차곡 꾸민 트리가 선물을 준비했어요!’ (2026-10-16 문구 확정).
