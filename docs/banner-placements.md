# 배너 광고 지면 (2026-10-19)

## 배치

| 화면 | 지면 | 설정 키 | 형식 |
| --- | --- | --- | --- |
| 로딩 | 캐릭터·안내 문구 아래 첫 번째 | `LOADING_LIST_AD_GROUP_ID` | 텍스트 중심 리스트형 1개 |
| 로딩 | 리스트형 아래 두 번째 | `LOADING_IMAGE_AD_GROUP_ID` | 이미지 피드형 1개 |
| 홈 바깥 하단 | 이용안내·보상내역이 포함된 홈 장면 종료 후 24px 간격 | `BANNER_AD_GROUP_ID` | 설정한 리스트형 또는 피드형 1개 |

트리·화분·러그·장식 배치 영역 안에는 광고 DOM을 넣지 않는다. 사진 저장과 공유는 `.home` 내부 장면만 추출한다. 배너는 공유 이미지에 들어가지 않는다.

하단 배너는 화면 고정형이 아닌 일반 스크롤 영역이다. 로딩 화면의 배너와 캐릭터·문구는 별도 세로 흐름으로 배치하고 작은 화면에서는 로딩 영역 자체가 스크롤된다. 이미지 광고 높이를 임의로 잘라내지 않는다.

## 동작

- 공식 `TossAds.initialize` / `TossAds.attachBanner`를 사용하며 별도 번들 `src/native-banner.js`로 SDK를 로드한다.
- SDK 초기화는 공유하고, 홈 로딩 완료를 광고 로딩/노출과 연결하지 않는다. 광고 노출을 위해 로딩 시간을 인위적으로 늘리지 않는다.
- 로딩 완료 또는 실패 시 로딩 배너를 제거한다. 이미 로딩 화면이 사라진 뒤 초기화가 끝나도 광고를 뒤늦게 부착하지 않는다.
- 배너 ID 미설정, 미지원 환경, 설정/API/SDK 실패, 광고 없음에는 해당 지면을 접는다. 광고 영역 대신 임의의 가짜 광고나 대체 CTA를 표시하지 않는다.
- 홈은 페이지 이탈 때 배너 인스턴스를 제거하고 캐시된 페이지 복귀 때 한 번만 재부착한다. 자체 주기적 새로고침은 하지 않는다.
- 날짜 테스트(`preview=1`)에서는 배너를 요청하지 않는다.
- 배너의 노출·클릭은 장식 획득, 슬롯 해제, 포인트 적립·교환, 일일 10개 한도와 연결하지 않는다.

## 운영 설정

Worker의 위 설정 키에 각 광고 그룹 ID를 넣는다. `LOADING_LIST_AD_GROUP_ID`는 리스트형, `LOADING_IMAGE_AD_GROUP_ID`는 이미지 피드형으로 콘솔에서 발급한 ID를 사용해야 한다. 같은 로딩 광고 ID를 두 번 설정하면 두 번째 지면은 표시하지 않는다. 서로 다른 ID라도 같은 포맷을 중복 배치하지 않도록 콘솔 유형을 확인한다.

이 변경에 운영 ID를 하드코딩하거나 콘솔 광고 그룹을 생성하는 작업은 포함하지 않는다. 설정되지 않은 광고는 숨긴다. 새 설정은 Worker `/api/config`에서 공개되므로 AIT 재빌드 없이 ID를 변경할 수 있다. 프론트엔드 광고 코드 최초 적용에는 새 AIT 배포가 필요하다.

개발/실기기 검증에는 공식 테스트 ID를 사용한다.
- 리스트형: `ait-ad-test-banner-id`
- 이미지 피드형: `ait-ad-test-native-image-id`

같은 화면의 동일 포맷 중복 배치 금지 등 광고 정책은 운영 전에 다시 확인한다. 리스트형·피드형을 지정했다고 개별 배치 심사 통과를 보장하지는 않는다. SDK의 Ad 표기·광고 콘텐츠를 변경하거나 게임 버튼처럼 꾸미지 않는다.

공식 문서: https://developers-apps-in-toss.toss.im/documentation/common/monetization/iaa/web-banner

## 검증 범위

Node 테스트로 SDK 초기화 공유, 실패/광고 없음 접힘, 비동기 이탈, 지면별 ID 분리, 촬영 범위 분리를 검사한다. 브라우저에서는 모의 SDK와 실제 앱 에셋으로 작은 화면 레이아웃 및 홈 전환 정리를 검사한다. 실제 광고 노출과 기기별 SDK 동작은 토스 테스트 환경에서 별도 확인해야 한다.
