# 트리 꾸미기 기획서 v0.6

작성일: 2026-10-15
최신 변경(2026-10-16): 선물 4 + 미니카 1 + 인형 1 + 오너먼트 22 + 전구 줄 1 + 마지막 별 1 = 총 30회. 이전 시안 7번 아이보리 리본은 제외하고 따뜻한 노란 전구 줄 한 묶음을 추가한다. 상세 최신안은 v0.6 절을 따른다. 화분은 리본 없는 나무 화분을 유지한다.
상태: 게임 규칙 기획 및 미확정 비주얼 콘셉트. 포도 키우기 구조를 재사용하는 에셋 교체형 게임.

> 최신 기준은 v0.5다. 트리 본체의 붓터치·5색, 리본 없는 화분, 개별 선물 디자인은 승인 시안을 따른다. 상단 5개 슬롯/중앙 1개 보기, 첫 트리 그린 고정 및 추가 트리 랜덤, 총 30회와 마지막 별을 유지한다. 선물·장난감도 출석 꾸미기에 포함하고 그만큼 가지 오너먼트를 줄인다. 구체적인 출석 순서와 장난감 디자인은 제안 단계다. 일부 매달린 장식만 가끔 흔들리고 트리·화분·바닥 소품은 고정한다.

## 1. 핵심 콘셉트
매일 출석하여 크리스마스트리에 오너먼트를 하나씩 달고, 마지막 출석에 꼭대기 별을 달아 트리를 완성한다. 최대 5개의 트리를 보유하며, 상단의 트리 슬롯 5개 중 하나를 선택해 해당 트리만 중앙에 크게 표시한다.

0일차부터 완성 크기의 큰 초록색 트리 한 개가 있다. 첫 트리는 초록색으로 고정하며 추가 트리 네 개는 생성 시 색상을 무작위로 정한다. 출석으로 트리 크기나 가지 수가 커지는 것이 아니라 장식이 누적된다. 완성한 트리와 장식은 계속 남는다.

## 2. 포도 키우기와의 대응

| 포도 키우기 | 트리 꾸미기 |
|---|---|
| 기본 포도 식물 | 장식 없는 큰 트리 |
| 출석으로 포도알 추가 | 출석으로 오너먼트 하나 추가 |
| 마지막 성장 단계 | 꼭대기 별 부착 및 완성 |
| 상단의 화분 슬롯 5개와 개별 보기 | 상단의 트리 슬롯 5개와 개별 보기 |
| 출석 팝업·누적 출석 | 같은 위치·구조·동작 유지 |
| 미션·프로모션 보상 | 같은 조건·수치·지급 구조 유지 |
| 포도 관련 이미지·문구 | 트리·장식 이미지와 대응 문구로 교체 |

화면 배치, 버튼, 출석 처리, 광고 노출, 보상 조건, 다음 개체 생성 조건, 저장 방식은 원본을 기준으로 유지한다. 신규 재화·랜덤 뽑기·추가 광고 조건은 넣지 않는다.

이 초안은 저장소를 확인한 구현 명세가 아니다. 원본의 전체 출석 단계 수·보상 수치·5개 생성 조건은 구현 착수 시 현재 설정을 확인하여 그대로 복사한다. 이전에 제작한 1~18알 이미지를 전체 출석 기간으로 단정하지 않는다.

## 3. 출석과 장식 규칙
완성 구성은 총 30개다. 바닥 소품 6개, 오너먼트 22개, 전구 줄 1개, 마지막 별 1개를 합해 30회째 완성한다(N=30). 전구 줄 전체를 한 번의 출석 소품으로 취급한다. 세부 획득 순서는 제안값이며 하루 1개와 총 30회는 유지한다.

| 단계 | 화면 상태 | 이번 출석으로 추가되는 것 |
|---|---|---|
| 0일차 | 큰 트리 1개와 받침만 표시 | 없음 |
| 1일차 | 첫 꾸미기 소품 1개 | 고정 순서에 따른 소품 1개 |
| 2~N-1일차 | 앞서 놓은 모든 소품 유지 | 트리 오너먼트 또는 바닥 소품 1개 |
| N일차 | 꼭대기 별이 달린 완성 트리 | 별 1개 |

완성 시 장식 총 N개는 트리 오너먼트와 바닥 소품을 합한 N-1개 및 꼭대기 별 1개다. 마지막 날에도 추가 장식은 정확히 한 개다. 별은 이전 단계에 미리 표시하지 않는다. 화분과 배경에 이미 있는 양말 등은 출석 장식 수에 포함하지 않는다.

출석 완료 후 ‘오늘의 장식 달기’를 누르면 미리 정한 위치에 자동 부착한다. 이 동작은 원본의 성장 연출 버튼 흐름에 맞춘다. 자유 드래그 배치나 장식 선택 기능은 이번 버전에 넣지 않는다.

하루 중복 수령, 출석 초기화 기준, 결석 시 처리, 누적·연속 출석 판정은 원본과 동일하다. 결석만으로 장식을 없애는 새로운 규칙은 추가하지 않는다.

## 4. 장식 종류와 배치
일반 장식은 빨강·금색·아이보리 구슬, 리본, 종, 사탕 지팡이, 눈송이 등으로 구성한다. 순서와 위치는 고정해 매일 다른 장식이 추가되는 모습이 분명하게 보이도록 한다.

초기에는 눈에 잘 띄는 중앙 가지에 배치하고 이후 좌우와 위아래를 번갈아 채운다. 장식끼리 심하게 겹치거나 트리 바깥에 뜨지 않도록 슬롯을 정한다. 별 전용 슬롯은 꼭대기 중앙 한 곳이다. 구슬·종·눈송이에 작은 얼굴을 넣어 포도 게임의 친근한 분위기를 이어갈 수 있다.

전구나 긴 가랜드를 별도 장식으로 사용한다면 하나의 출석 단계에 한 에셋만 추가한다. 자동으로 여러 소품이 함께 생기는 연출은 피한다.

## 5. 상단 트리 슬롯 5개와 개별 보기
포도 키우기처럼 화면 상단에 트리 슬롯 5개를 둔다. 슬롯을 누르면 선택한 트리 한 개만 중앙에 크게 표시한다. 다섯 트리를 한 화면에 나란히 배치하거나 앞뒤로 전시하지 않는다.

각 슬롯은 해당 트리의 작은 아이콘과 진행·완료 상태를 보여주며, 선택한 슬롯은 테두리 등으로 구분한다. 아직 생성하지 않은 슬롯은 원본 화분 슬롯과 동일한 방식으로 표시한다. 완성한 트리도 슬롯에 남아 다시 선택해 볼 수 있다.

최대 수량, 추가 생성 시점, 출석 적용 대상과 범위는 원본과 동일하게 유지한다. 트리가 여러 개라는 이유로 하루 장식 지급 횟수를 새로 늘리지 않는다. 트리마다 진행도, 붙은 장식, 완료 여부를 개별 보관하며 슬롯을 전환해도 서로 섞이지 않는다.

중앙 트리의 표시 영역과 크기는 슬롯 수에 따라 축소하지 않는다. 장식은 선택한 트리의 진행도에 맞춰 표시한다.

### 트리 색상 규칙
- 첫 번째 트리는 초록색으로 고정한다.
- 두 번째~다섯 번째 트리는 생성 시 색상을 무작위로 한 번 결정한다.
- 색상은 클래식 그린·스노우 화이트·블러썸 핑크·아이스 블루·샴페인 골드 5종으로 확정한다. 동일한 형태에 색상만 변화를 준다.
- 구현 기본안은 다섯 색상 동일 확률(각 20%)이며 중복을 허용한다. 추가 트리에서도 초록색이 나올 수 있다. 이는 초기 제안값이며 사용자 확정 사항과 구분한다.
- 결정한 색상을 트리별로 저장한다. 슬롯 전환·출석·재접속·완성 시 다시 추첨하지 않는다.
- 상단 슬롯 썸네일은 실제 트리의 색상과 장식 진행도를 반영한다. 미완성 썸네일에 별을 미리 표시하지 않는다.
- 색상은 외형에만 영향을 준다. 출석 필요 횟수·보상·장식 지급·완성 조건은 동일하다.
- 모든 색상의 트리는 생성 시 장식이 없으며 마지막 출석에만 별을 단다.
- 색상별 트리 에셋은 형태·크기·장식 부착 좌표를 통일한다.
- 색상 식별자(treeColor)는 트리 생성 데이터와 함께 저장한다. 생성 재시도로 기존 색상이 바뀌지 않게 한다.

## 6. 화면과 문구
- 메인: ‘트리 꾸미기’, 누적 출석, 현재 진행도, 상단 트리 슬롯 5개와 선택 트리 표시 영역, 기존 출석·미션 버튼.
- 출석 완료: ‘오늘도 반가워요!’와 당일 장식 이미지, ‘장식 달기’ 버튼.
- 장식 부착 후: ‘오늘의 장식을 달았어요!’라는 짧은 피드백.
- 완성: ‘반짝이는 트리 완성!’과 별 부착 연출, 원본과 같은 보상 확인 흐름.
- 미션: 기존 x일 달성·보상 금액과 지급 동작 유지. 관련 아이콘만 트리 소품으로 변경.

원본의 주아체와 둥근 버튼·팝업 분위기를 유지한다. 출석 팝업 아래의 중복 ‘몇 일차 출석 완료’ 문구는 넣지 않는다. 새 게임의 운영 상태와 무관한 지급 테스트 안내 문구를 임의로 추가하지 않는다.

## 7. 시각 방향
부드러운 2D 캐주얼 일러스트. 짙은 초록 트리, 빨강·금색 장식, 크림색 UI와 따뜻한 목재 받침을 사용한다. 배경은 눈 내리는 창문이 있는 아늑한 실내를 제안한다. 기존 배경을 이 테마로 교체하되 버튼과 주요 정보의 위치는 유지한다.

0일차는 이미 큰 트리가 보이는 구도다. 진행 중에는 장식 누적이 명확히 보이고, 완성 시에만 꼭대기에 별이 등장한다. 시안은 시각 방향 제안이며 실제 원본 화면을 픽셀 단위로 복제한 결과가 아니다.

## 8. 에셋 분리 명세
| 에셋 | 역할 | 제작 기준 |
|---|---|---|
| 실내 배경 | 공통 배경 1장 | 트리·받침·UI를 포함하지 않음 |
| 기본 트리 | 그린·화이트·핑크·블루·샴페인 골드 5색 원본 | 형태·크기·부착 좌표 통일, 장식·별·받침 없는 투명 배경 |
| 받침·화분 | 각 트리 아래 배치 | 트리와 분리된 투명 이미지 |
| 일반 장식 | 일차별로 한 개 부착 | 종류별 독립 투명 이미지, 필요 시 재사용 |
| 꼭대기 별 | 마지막 날 전용 | 투명 배경, 중심 정렬 |
| 반짝임 | 장식·완성 피드백 | 게임 오브젝트와 분리 |
| UI 아이콘 | 출석·미션·완성 | 기존 아이콘 크기와 비율 유지 |

기본 트리는 예시로 1024px급 원본, 장식은 256px급 원본으로 제작하고 최종 크기는 원본 렌더링 크기에 맞춘다. 같은 에셋을 5개 트리의 개별 보기에서 재사용한다. 트리와 부착 장식은 같은 부모 좌표계에 묶어 함께 축소한다. 슬롯은 트리 기준 정규화 좌표로 저장해 크기가 달라져도 위치가 어긋나지 않게 한다.

완성 단계마다 통이미지를 새로 생성하지 않는다. 배경 → 선택한 트리 그룹 1개 → UI 순서로 그리고, 트리 그룹 내부에서는 받침 → 트리 → 일반 장식 → 별 → 효과 순서를 사용한다.

## 9. 데이터와 구현 범위
출석 기록, 보상 처리, 광고, 로그인, 저장 구조는 원본을 재사용한다. 기존 성장 단계 값으로 표시할 장식 수를 결정하고 트리별 장식 슬롯 목록을 테마 설정으로 관리한다. 별도 장식 인벤토리 시스템은 만들지 않는다.

포도 게임과 별도 앱으로 운영할 경우 사용자 진행도·보상 기록이 섞이지 않도록 앱 식별과 데이터 구분은 필요하다. 포도 게임에서 쌓은 출석을 자동 이전하는 기능은 이번 범위에 포함하지 않는다.

## 10. 확인 기준
- 신규 시작 시 장식과 별이 없는 큰 초록색 트리 한 개가 보인다.
- 2~5번째 트리는 생성 시 색상이 추첨되며 재접속·출석·슬롯 전환 후에도 유지된다.
- 상단 슬롯과 중앙 트리의 색상·진행도가 일치한다.
- 출석 한 번당 정확히 장식 하나가 추가된다.
- 재접속 후 장식 위치와 진행도가 유지된다.
- 마지막 출석에서만 별이 꼭대기에 붙는다.
- 완성까지 필요한 출석 수와 보상은 원본과 일치한다.
- 상단 슬롯 5개를 전환하면 선택한 트리 한 개만 중앙에 표시되며, 각 트리의 장식·별·진행도가 정확히 유지된다.
- 6번째 트리는 생성되지 않는다.
- 출석·광고·프로모션 지급 흐름은 에셋 교체 전과 동일하게 동작한다.

## 11. 제작 순서
1. 현재 포도 키우기 설정과 화면을 기준으로 단계 수·보상·생성 조건 확정.
2. 기본 트리, 받침, 장식, 별, 배경을 각각 제작.
3. 일차별 장식 종류와 부착 좌표 설정.
4. 기존 화면에 테마와 대응 문구 적용.
5. 0일차·진행 중·완성·상단 5개 슬롯 전환 및 기존 지급 흐름 확인.

게임명은 임시로 ‘트리 꾸미기’를 사용한다. 신규 기능 없이 포도 키우기의 구조를 그대로 적용하는 것이 이번 버전의 기준이다.

## 시안 정정
초기 이미지의 네 번째 화면에 있는 트리 5개 동시 전시는 적용하지 않는다. 최종 UI는 상단에 작은 트리 슬롯 5개, 중앙에는 선택한 트리 한 개를 크게 표시하는 구조다.

2. [초기 성장 비교 시안](images/tree-growth-early-concept.png): 빈 트리·장식 누적·별 완성 모습 참고용. 네 번째 패널의 5개 동시 전시는 폐기된 구도이며 구현하지 않는다.

두 이미지 모두 트리·오너먼트 최종 디자인을 확정하지 않는다. 배경, UI 세부 디자인, 장식 종류와 수량도 이미지 그대로 구현하라는 의미가 아니다. 문서의 게임 규칙이 시안보다 우선한다.

## v0.3 기록: 트리 형태·장식 수·모션 (2026-10-15)

이 절의 오너먼트 29개 및 3·4·6·7·9 배치 제안은 v0.5에서 대체되었다. 트리 고정과 일부 오너먼트의 간헐적 모션은 유지한다.

### 색상과 생성
- 첫 트리는 클래식 그린 고정. 두 번째부터 그린을 포함한 확정 5색 전체를 랜덤 후보로 사용한다.
- 스노우 화이트는 우윳빛, 블러썸 핑크는 딸기우유색, 아이스 블루는 화이트와 구별되는 하늘색, 샴페인 골드는 부드러운 금색을 기준으로 한다.
- 골드 트리에서도 마지막 별이 보이도록 별은 더 진한 금색과 명도 차이를 확보한다.
- 색상은 확정이며 트리 실루엣·화분·오너먼트의 구체적인 그림 디자인은 시안 검토 후 확정한다.

### 29개 장식을 고려한 형태와 배치 시안
- 일반 오너먼트 29개와 마지막 꼭대기 별 1개의 공간을 확보한다. 화분과 트리 본체는 장식 개수에 포함하지 않는다.
- 넓은 하단과 장식을 걸 수 있는 충분한 가지 면적을 가진 5단 트리를 우선 시안으로 검토한다.
- 위에서부터 3·4·6·7·9개(합계 29개) 배치를 제안한다. 정확한 좌표와 부착 순서는 시안에서 겹침·가독성을 확인한 뒤 확정한다.
- 각 줄의 높이를 조금씩 엇갈리게 하고 별 전용 꼭대기 공간을 남긴다.
- 화분은 작고 단순한 형태로, 줄기를 조금 드러내 하단 장식과 겹치지 않게 한다.
- 0개·진행 중·29개가 찬 상태를 모두 확인한다. 29개를 무리하게 작게 줄여 넣지 않는다.

### 대기 모션 확정
- 트리 본체·가지·줄기·화분은 고정한다. 트리 전체 흔들림과 가지 끝 살랑임은 적용하지 않는다.
- 이미 부착된 오너먼트 중 몇 개만 가끔, 서로 다른 타이밍에 흔든다. 29개 전체의 동시·상시 흔들림은 금지한다.
- 장식이 가지에 매달린 부착점을 회전 중심으로 삼고 위치 이동이나 확대·축소는 대기 모션에 사용하지 않는다.
- 강도와 속도는 포도 키우기 잎 모션과 같은 수준으로 맞춘다. 확인한 원본은 `src/style.css`의 `leaf-breeze` 좌우 ±3°, ease-in-out이며 개별 주기·지연은 `Leaves.tsx`에 있다. 실제 적용 전 최신 원본 값을 다시 확인한다.
- 간헐적 재생의 초기 구현 제안: 동시에 최대 2~3개, 1~2회 부드럽게 왕복한 후 정지하고 쉬는 시간을 둔다. 정확한 개수·휴지 시간은 실기기에서 확정한다.
- 화면 진입이나 슬롯 전환 때 모든 장식의 모션이 동시에 시작되지 않게 한다. 화면 밖·비활성 트리의 모션은 중단한다.
- 움직임 줄이기 설정에서는 대기 모션을 끈다. 흔들림으로 슬롯 좌표·출석 상태·보상이 변경되지 않는다.

### 에셋 제작 기준 추가
- 배경·트리·화분·오너먼트·별은 각각 분리한다. 고정 가지를 애니메이션용 레이어로 추가 분리할 필요는 없다.
- 오너먼트는 부착점 좌표를 정의할 수 있도록 상단 고리와 여백을 일관되게 제작한다.
- 5색 트리의 실루엣과 크기, 장식 29개 및 별의 부착 좌표를 통일한다.
- 이번 트리 시안은 디자인 검토용이다. 장식이 그려진 완성 시안을 실제 분리 에셋으로 사용하지 않는다.

- 일반 장식 29개와 마지막 별 1개, 고정 트리 및 일부 장식만 간헐적으로 흔드는 규칙은 유지한다.
- 기존 홈화면 시안은 UI 배치 참고용으로 유지하며, 실제 트리 그림체는 이 최종 승인 원본을 따른다.

## v0.5 최신: 선물·장난감 출석 꾸미기 및 단순 화분

이 절의 오너먼트 23개 구성은 v0.6의 오너먼트 22개와 전구 줄 1개로 대체한다.

- 사용자 확정: 선물 상자·미니카·인형 같은 바닥 소품도 출석 1회당 꾸미기 1개에 포함한다. 그 수만큼 트리 오너먼트를 줄인다. 총 30회 및 마지막 날 별은 유지한다.
- 초기 수량 제안: 선물 상자 4개 + 미니카 1개 + 곰 인형 1개 + 트리 오너먼트 23개 + 별 1개 = 30개. 미니카·인형의 구체 디자인과 획득 순서는 아직 제안이다.
- 선물 묶음 통이미지로 여러 상자를 한 번에 지급하지 않는다. 상자마다 독립 PNG·식별자·출석 단계·바닥 좌표를 갖는다.
- 초기 0일차에는 바닥 선물·장난감도 없다. 소품이 놓인 홈 시안은 완성/배치 참고이며 0일차로 그대로 구현하지 않는다.
- 트리와 화분은 기본 제공이며 지급 횟수에 포함하지 않는다. 바닥 소품도 선택한 트리별로 소유·진행도를 저장한다.
- 최상단 진행도는 바닥 소품까지 합산한 ‘꾸미기 x/30’으로 안내한다. 트리 오너먼트만 따로 수량을 표시할 경우 전체 진행도와 구분한다.
- 좌우에 낮은 소품을 비대칭으로 배치한다. 선물은 일부 화분을 가릴 수 있으나 트리 가지·미래 오너먼트·출석 버튼·벽난로 불을 가리지 않는다.
- 화분은 큰 리본 없는 단순한 나무통으로 교체한다. 나무 질감과 어두운 테는 유지한다. 기존 리본 화분은 현재 사용 에셋에서 제외하고 이전 버전은 Git 이력에서 복구할 수 있다.
- 선물의 붓터치·색면·명암·불빛 방향을 트리와 통일한다. 바닥 소품 대기 모션은 기본 고정, 가지에 매달린 일부 오너먼트만 기존 포도 잎 수준으로 간헐적으로 흔든다.
- 바닥 소품 공간이 생겼으므로 기존 29개 오너먼트 배치 좌표를 그대로 쓰지 않는다. 초기 제안 23개는 2·3·5·6·7 분산 배치를 검토하되 실제 크기와 흔들림 여백을 보고 확정한다.
- 출석·보상 서버 구현은 이번 변경에 포함하지 않는다. 선물 4개와 화분 에셋을 우선 제작하며 미니카·인형 에셋과 트리 오너먼트는 후속 제작 대상이다.

자세한 파일·순서 제안은 [바닥 소품 명세](assets/floor-decorations.md)를 참고한다.

- 기존 장식을 직접 누르거나 메인 ‘장식 배치’ 목록에서 선택해 옮긴다.
- 장식 전체 경계로 판정하며 별 전용 꼭대기·화분·하단 UI 영역을 침범하지 않는다. 별·전구 줄은 고정한다.
- 좌표는 화면 비율 기준으로 트리별 저장한다. 저장 좌표는 재접속 시 획득 여부와 경계를 다시 검증한다.
- 실제 모바일 터치·시각 검증은 별도로 필요하다.


## v1.0 시작 로딩 화면 (2026-10-16)
- 승인된 크림색 크리스마스 배경을 유지하고 캐릭터·문구는 별도 레이어로 표시한다. 게이지·퍼센트·상태 점등은 없다.
- 산타가 루돌프를 탄 3프레임 투명 스프라이트를 0.6초 주기로 전환하고 몸을 약 5px 위아래로 움직인다. 모션 감소 설정에서는 캐릭터를 정지한다.
- `트리 꾸미러 들어가는 중` 뒤의 점이 400ms마다 0→1→2→3→0개로 반복한다.
- 로딩 종료 조건: 저장 상태 복구, 장식 manifest 수신·검증, 현재 트리 및 획득 장식 디코딩/렌더링, 홈 배경·불꽃·슬롯 이미지 디코딩 완료 후 화면 그리기 시점. 현재 서버는 미연동이므로 실제 서버 데이터 대기 기능으로 오인하지 않는다. 추후 API 초기화도 이 준비 작업에 포함해야 한다.
- 임의 최소 노출 시간이나 가짜 진행률 없이 준비되면 즉시 종료한다. 준비 중 홈은 inert/숨김으로 입력을 차단한다.
- 실패 또는 25초 준비 시간 초과는 홈을 노출하지 않고 재시도 버튼을 제공한다. 재시도는 앱을 새로 불러온다.
- 에셋: `assets/loading/cream-background.png`, `assets/loading/santa-rudolph-run.png`. 배경·스프라이트는 승인 참고 이미지를 사용해 이미지 생성 도구로 제작했다.

## v1.1 연속 출석 마무리 (2026-10-16)
이전 결석 후 계속 꾸미기 규칙을 대체한다. 트리별 연속 출석 중 하루 전체를 쉬면 장식 추가·배치를 마무리하고 출석한 날까지의 누적 포인트를 광고 후 수령한다. `광고 보고 모은 포인트 받기`라는 긍정적인 버튼 문구를 쓴다. 실제 지급은 서버/광고 검증 어댑터 연결이 필요하다. 상세 계약은 `attendance-settlement.md`를 따른다.

## v1.2 사용자 선택으로 슬롯 생성 (2026-10-19)
이전 첫 출석 자동 생성 및 앞 슬롯 출석 조건을 대체한다.
- 첫 초록 트리는 기본 제공한다. 2~5번 슬롯은 + 버튼으로 표시하고, 누른 슬롯에만 트리를 생성해 선택한다.
- 이전 트리의 출석 여부와 관계없이 어느 슬롯부터든 생성할 수 있다. 생성은 출석으로 세지 않는다.
- 추가 트리 색상은 생성 시 기존 5색 중 무작위로 정하고 저장한다. 이후 슬롯 전환과 재접속으로 바뀌지 않는다.
- 출석은 선택한 트리만 진행한다. 다음 트리를 자동 생성하지 않는다. 하루 1회 및 광고 완료 조건은 유지한다.
- 저장 데이터의 슬롯 번호는 바꾸지 않는다. 중간 미생성 슬롯은 null로 보존하며 기존 트리의 출석·색상·배치·보상 기록은 유지한다.
- Worker 출석에서도 앞 슬롯 조건만 제거한다. 인증, 슬롯별 광고 ID, 날짜와 횟수의 서버 계산, 프로모션 중복 방지는 유지한다. DB 스키마 변경은 없다.
