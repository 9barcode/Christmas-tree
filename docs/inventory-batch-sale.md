# 선택 묶음 판매

- 판매하기 탭에서 실제 보유 장식 단위를 체크하여 전체 1~3개 선택한다. 종류가 달라도 함께 판매할 수 있으며 3개를 채울 필요는 없다.
- 선택한 장식에 placed=1이 있으면 광고 호출 전에 팝업을 표시한다. 본문은 `판매할 수 없어요.` 뒤 줄바꿈 후 `트리에 배치된 장식이 있어요!`이다.
- 광고 1회 완료 후 선택 장식의 판매 가치 합계를 적립한다. 배치된 장식은 개별 판매로 회수하거나 판매하지 않는다.

## 서버 연동

`POST /api/v3/ads/reserve`에 `{purpose:'sell', itemIds:[...]}`를 전송한다. 서버는 소유권, 미판매 상태, 판매 가치, 배치 상태와 최대 3개 제한을 광고 예약 전에 검증한다.

광고 완료 후 `POST /api/v3/sell`에 `{itemIds:[...], adRequestId}`를 전송한다. 예약한 선택 목록과 일치해야 한다. 서버는 배치 여부를 다시 확인하고, 전체 목록이 유효한 경우에만 트랜잭션으로 합계 적립·판매 표시·광고 소비를 처리한다. 동일 요청 재시도는 중복 적립하지 않는다. `item_placed` 오류는 프론트에서도 동일 팝업으로 표시한다.

기존 단일 `itemId` 요청도 지원한다. 기존 ad gate의 item_id TEXT에 단일 ID 또는 정렬된 ID 배열 JSON을 저장하므로 DB 마이그레이션은 필요 없다. 프론트 빌드와 함께 업데이트된 worker/factory.js 서버 코드도 배포해야 한다.
